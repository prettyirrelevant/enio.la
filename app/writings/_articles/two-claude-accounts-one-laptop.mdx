# Two Claude accounts, one laptop.

I have separate Claude Pro accounts for work and personal projects. Work code lives
under `~/Developer/Work/Acme`, and everything else is personal. I wanted the current
directory to pick the account automatically.

_Updated 7 October 2026 after Anthropic documented multiple-account support._

## The supported mechanism

Anthropic now documents
[multiple accounts](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)
through `CLAUDE_CONFIG_DIR`. Each directory gets its own claude.ai login, settings,
session history, and plugins.

This also works on macOS. Claude Code keys each Keychain entry to its configuration
directory, so the profiles do not overwrite each other's login.

## Route by directory

I put this script at `~/.local/bin/claude`, before the real Claude binary on `PATH`:

```sh
#!/bin/zsh
set -eu

cwd="${PWD:A}"
work_root="$HOME/Developer/Work/Acme"

if [[ "$cwd/" == "$work_root/"* ]]; then
	export CLAUDE_CONFIG_DIR="$HOME/.claude-work"
	account="work · work@example.com"
else
	export CLAUDE_CONFIG_DIR="$HOME/.claude-personal"
	account="personal · me@example.com"
fi

[[ -t 2 ]] && print -u2 -- "claude: $account"

exec /absolute/path/to/the/real/claude "$@"
```

Run `command -v claude` before installing the script, then replace the final command
with that absolute path. The absolute path prevents the script from calling itself.

The trailing slashes enforce a directory boundary. A directory such as `Acme-archive`
therefore stays on the personal account.

Run `claude auth login` once inside the work tree and once outside it. Run
`claude auth status` in both locations to verify the selected email address.

## Caveats

- The profile is selected at launch. Changing directories inside a session does not
  change its account.
- The profiles do not share user settings, history, plugins, or user-level memory.
  Project files remain shared through the normal filesystem.
- `ANTHROPIC_API_KEY` takes precedence over a Claude Pro login. Remove it when you want
  subscription usage.
- This separates application state rather than operating-system access. An
  [open report](https://github.com/anthropics/claude-code/issues/80580) also describes
  user-level `CLAUDE.md` leakage between profiles.
